# 사전 등록 (Pre-registration) v1.3 — 상담기관 AI 취업상담사 실험

등록 시점: 2026-09-24 (v1.0) · 개정 2026-09-25 (v1.1, v1.2, v1.3) · 루브릭 동결 태그 `rubric-freeze-v2.2.1` (rubric.md v2.2 / judge_prompt.md v1.6) · 사전 등록 태그 `prereg-v1.3`
이 문서 이후의 설계 변경은 버전을 올려 별도 등록하고, 이전 결과는 분리 집계한다.

## 1. 연구 질문과 가설 (방향 사전 명시)
- RQ1 갈래 특화: C3(코어+5갈래 델타+도구) 가 C2(코어+도구) 보다 우수하다. **H1: C2→C3 페어와이즈 B 승률 > 0.5, 95% CI 하한 > 0.5.**
- RQ2 자동 최적화: C4(GEPA/MIPROv2 최적화 프롬프트) 가 C3 보다 우수하다. **H2: C3→C4 B 승률 > 0.5, CI 하한 > 0.5.**
- RQ3 심판 신뢰도: 3심판 다수결과 인간 다수결의 일치도 — P5 소급 앵커에서 ICC(2,k) ≥ 0.60(차원), κ ≥ 0.70(F1~F7). P4 종료 전에는 검정하지 않는다.
- RQ4 피드백→시드: 실서비스 행동 결함 전 건이 시드/루브릭에 매핑(S6) — 기술 통계로 보고, 가설 검정 없음.
- 사다리 확인(H0/H1 보조): C0→C1→C2 는 각 단계 B 승률 > 0.5 를 기대하나 확증 가설이 아니다(파이프라인 타당성 확인용).

## 2. 설계
- 조건: C0 바닐라 / C1 코어 프롬프트 / C2 +도구 / C3 +갈래 델타 / C4 +자동 최적화 (`lab/conditions.py`).
- 시나리오: 갈래 5 × 30 = 150 페르소나(`persona_gen`, 은닉 프로필·행동유형 6종 균등), 시드 3 → 조건당 450 세션, 전체 2,250 세션(S3).
- 세션: 최대 8 내담자 턴, 10분 타이머, 런타임 claude-sonnet-4-6, 시뮬레이터 claude-sonnet-4-6.
- 페어와이즈: 동일 (페르소나, 시드) 쌍, 위치 무작위(스왑 기록), 비교쌍 = (C0,C1),(C1,C2),(C2,C3),(C3,C4).
- C4 프롬프트: 갈래별 GEPA 최적화(회귀 게이트 통과 후보만), 최적화용 페르소나는 본실험 페르소나와 **분리**(held-out) — 지표 해킹 통제(S4).

## 3. 판정 (정책 v2, J1~J3)
- 정본 위계: 코드 검증기(F1·F4·F6 전체, F5 반복 성분, F7 직업명 성분) > 이종 3심판 다수결(F2·F3·F5-잔여·F7-잔여, 점수 7차원).
- 심판: claude-opus-4-6 + 타사 모델 1(키 투입 후 확정, 온보딩 절차 `lab.onboard_judge` 통과 필수) + claude-sonnet-4-6. 3심판 미확보 시 C4 채점은 시작하지 않는다.
- 판정 불능(동률·유효 심판 부족)은 제외하지 않고 건수를 공개하며, 주 분석은 판정 가능 세션으로 한다(민감도 분석: 불능 = 실패로 간주한 경우 병기).
- 합의율(J2): 배치마다 Fleiss κ(실패항목)·ICC(2,k)(점수)를 산출·공개. κ<0.60 항목은 플래그하고 해석에서 강등한다.

## 4. 결과 변수
- **주 결과**: RQ1/RQ2 각각 페어와이즈 B 승률(3심판 다수결, tie=0.5), 시나리오 단위 부트스트랩 95% CI(2,000회).
- 부 결과: 종합점수(점수 중앙값 평균 − 실패 페널티 − 길이 페널티) 쌍대 차이의 Wilcoxon 부호순위, 실패율 F1~F7, 커버리지(심판 중앙값·코드).
- 다중비교: 확증 가설 2개(H1, H2) + 사다리 보조 2개 → Holm 보정, α=0.05.

## 5. 제외·중단 규칙
- 세션 오류(API 실패·안전 정지)는 재실행 1회, 그래도 실패하면 제외하고 건수 공개.
- 심판 실패 세션은 재개(resume)로 재채점, 최종 유효 심판 <2 인 세션은 제외·공개.
- 본실험 시작 게이트(v1.3): 판정 불능 세션 0 · 유효 심판 3 · 점수차원 ICC(2,k) 전부 ≥ 0.60 · 카나리아 100% · 루브릭 동결 확인. C4 는 추가로 유효 심판 ≥3 가드.
  F7-잔여·F5-잔여 κ 는 게이트 조건이 아니라 기록·공개 항목이며 배치별 등급(κ ≥ 0.60 확증, 미만 탐색적)을 자동 판정한다. F7 사다리는 비증가(C0 ≥ C2 ≥ C3)로 기록한다.
- 중간 분석 없음. 본실험은 1회 실행하며, 재실행은 파이프라인 결함이 확인된 경우에만 하고 사유를 기록한다.

## 6. 성능 전망 (§6.0) 과 지표 등급
### §6.0 사전 전망 (스모크 런 75세션·2심판 참고치 기반, 결론 아님)
| 비교 | 전망 B 승률 | 근거 | 판정 |
|---|---|---|---|
| C0→C2 | 0.85~0.95 | 스모크 0.92 [0.80, 1.00]; 형식 규칙·도구 근거 효과 | 사다리 확인 |
| C2→C3 (H1) | 0.60~0.70 | 스모크 0.71 [0.53, 0.86] (2심판 다수결·n=24) — 효과는 exploration·branch_fit 에 집중 | 확증 |
| C3→C4 (H2) | 0.55~0.65 | 스모크 데이터 없음. GEPA 가 회귀 게이트 안에서 형식·행동 우선 규칙을 강화한다는 가정 | 확증 |
| 최소 검출 효과 | 승률 0.55 | 시나리오 450쌍 기준 SE ≈ 0.024 → 0.5 대비 0.55 는 CI 하한 > 0.5 로 검출 가능 | — |
전망을 벗어난 결과(예: H2 승률 ≤ 0.5)는 negative result 로 보고하며(handoff-tasks P4-2 정체 사다리 ④), 사후 조정하지 않는다.

### 지표 등급
- **확증(confirmatory)**: 페어와이즈 승률(H1·H2), F1·F4·F6(코드), F7(코드 성분 + 잔여; 잔여는 배치 κ ≥ 0.60 일 때만 확증 등급 유지, 미달 배치는 탐색적으로 강등).
- **탐색적(exploratory)**: **F5-잔여(재질문·프로필 미반영)** — 스모크 재채점에서 κ 0.19(2심판) 로 낮아 확증 지표에서 제외. 매 배치 κ 를 공개하고 결과는 방향성 참고로만 쓴다. F2·F3 도 양성률이 낮아(<2%) 탐색적으로 둔다.
- **인간 병행**: empathy(공감·태도)는 ICC 가 가장 낮은 차원(0.61~0.73)이며 P5 소급 앵커의 1순위 검증 대상이다.

## 8. 개정 이력
- **v1.1 (2026-09-25, 본실험 데이터 수집 전)**: 루브릭 v2.1 → v2.2. F7-잔여 정의 명시화.
  사유: 타사 심판(openai/gpt-5.4) 온보딩 재채점에서 F7-잔여 Fleiss κ 0.31(기준 0.60 미달). 진단 결과 모델 편향이 아니라 정의 모호성 —
  v2.1 문구 "계획을 제시하지 않은 세션은 F7 이 아니라 B5 로 반영"을 gpt-5.4 는 문자대로 따라 계획 부재 세션(C0 전형)을 F7=False 로,
  opus/sonnet 은 계획 부재를 '추상적 계획'으로 읽어 F7=True 로 판정(C0 양성률 gpt 0.28 vs opus 0.88·sonnet 0.92, 쌍별 κ gpt~opus 0.25, opus~sonnet 0.61).
  결정(A안): 문자 해석(gpt) 쪽으로 정렬 — "계획 문장이 하나도 없으면 F7 아님(B5·F6 담당), 계획이 있되 기간·행동·확인방법 결여면 F7" + 예시 1쌍 추가.
  영향: 확증 가설(H1·H2)과 주 결과 변수는 변경 없음. F7 은 여전히 배치 κ ≥ 0.60 일 때만 확증 등급. 재동결 후 75세션 재채점·게이트 재판정
  (합격 기준: F7-잔여 κ ≥ 0.60 **및** F7 실패율 C0 > C2 > C3 사다리 유지) 통과 시 본실험 시작.
- 페르소나 격리(v0.0.9-4): 본실험 150개(P- 접두사)는 최적화기(C4 프롬프트 탐색)의 학습·선택 경로에 등장하지 않는다.
  최적화기는 학습용 T- 세트와 선택용 H- 60개만 접근하며, 코드 가드가 위반 시 즉시 중단한다.
- **v1.2 (2026-09-25, 본실험 데이터 수집 전)**: 심판 입력·검증기 결함 수정 (루브릭 정의 변경 없음).
  사유: v2.2 재채점에서 F7 κ 0.33·사다리 위반(C2 0.28 < C3 0.32). 진단: (a) 검증기가 "교육운영·사무"를 "교육운영·사"로 잘라 비표준 직업명으로 오탐(접미사 '사' 경계 미검사),
  (b) 심판 입력 블록에 그 코드 성분이 노출돼 opus/sonnet 이 "코드 판정이 True 이므로 F7=True"로 복사(잔여 판정 아님) — gpt 는 잔여만 판정해 불일치.
  조치: 검증기 접미사 뒤 한글 연속 시 후보 제외, 심판 입력에서 F5/F7 코드 성분 제거 + "잔여만 판정" 명시(judge_prompt v1.6). 재동결 `rubric-freeze-v2.2.1`.
- **v1.3 (2026-09-25, 본실험 데이터 수집 전) — 게이트 정합화 [P] + 엔진 수정 [R]**
  정합화 사유: 첫째, 사전 등록 §6 은 F7-잔여를 "배치 κ ≥ 0.60 일 때만 확증"인 조건부 지표로 정의했는데 온보딩 게이트는 같은 κ 를 본실험 시작의 필수 조건으로 요구해 문서와 절차가 서로 어긋났다.
  둘째, 세 차례 정의·입력 정정(v2.1→v2.2→v2.2.1)에도 교차 공급자 κ 는 0.31→0.33→0.36 에 머물렀고 남은 불일치는 C0 종결문 해석에 국한되며 주 비교 조건(C2·C3)에서는 세 심판이 완전히 일치했다.
  셋째, 따라서 F7-잔여 κ 는 게이트가 아니라 배치별 확증/탐색 등급 판정과 공개의 대상으로 두는 것이 사전 등록의 원래 취지(조건부 확증)와 일치하며, 필수 게이트는 심판 유효성(판정 불능 0·유효 심판 3·ICC ≥ 0.60)과 코드 검증기 건전성(카나리아 100%)으로 한정한다.
  [R] 엔진 수정(시스템 변경, 전 조건 공통): 고정 종결문의 "오늘 안에" 등 기간 주입 문구 제거(기간은 상담 내용에서만), save_journal 의 actions_next 는 내담자 수행 행동만 허용(스키마 밸리데이터가 상담사 주어 문장 거부, 1회 재요청 후 잔여 제거). 회귀 게이트·카나리아 재실행.
  정지 규칙(evaluation-policy v2.1): 동일 항목 정의 개정 3회 실패 시 탐색적 강등, 배치당 개정 1회 한도 — F7-잔여는 이 규칙에 의해 본 배치에서 탐색적으로 강등된 상태이며 본실험 배치 κ 로 재판정된다.
